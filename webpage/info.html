日本語

画面は WASM と tokio を適材適所で。HTML5・CSS3 は最小限

内容: RPoem / RPoRea は、画面の動きを Rust から WASM にして動かし、サーバー側は tokio の非同期処理で受けます。HTML5 と CSS3 は使いますが、なるべく少量にとどめ、見た目や動きの多くを Rust 側へ寄せます。

メリット: 画面とサーバーを同じ Rust で書けるので、型の食い違いが減ります。重い計算は WASM、通信待ちは tokio のように、仕事に合わせて使い分けられます。保守する HTML・CSS の量が少なくなります。

デメリット: いまの実測では、Reaxt の画面は元の React 版より転送量が約 1.8 倍でした(gzip 合計で約 119KB 対 約 68KB)。描画速度はまだ測っていません。出来合いの画面部品が少なく、Rust のコンパイルや WASM のデバッグにも手間がかかります。

English

UI with WASM and tokio where each fits; HTML5 and CSS3 kept minimal

What: RPoem and RPoRea run the UI logic as Rust compiled to WASM and handle the server side with tokio's async runtime. HTML5 and CSS3 are still used, but kept as small as possible, with most look-and-feel logic moved into Rust.

Pros: One language for UI and server means fewer type mismatches. You can pick the right tool per job: WASM for heavy computation, tokio for I/O waiting. There is less HTML and CSS to maintain.

Cons: In our current measurement the Reaxt page transfers about 1.8 times more than the original React build (roughly 119 KB vs 68 KB gzipped in total), and rendering speed is not measured yet. There are fewer ready-made UI components, and Rust compile times and WASM debugging take more effort.

English

No Node.js, JavaScript or TypeScript by design

Deutsch

Die gemeinsame Basis nur einmal installieren

Inhalt: Rechen- und KI-Bausteine wie open-cuda, aruaru-llm, open-cpu und open-directx werden pro Server nur einmal installiert, und jede Website ruft sie über Connect / gRPC auf. open-web-server übernimmt die Rolle von Apache, RPoem die von Tomcat.

Vorteile: Nichts wird pro Website installiert, das spart Speicherplatz und Arbeitsspeicher. Updates und Sicherheitskorrekturen gibt es an einer Stelle, ebenso Parallelitätsgrenzen und faires Anstellen.

Nachteile: Fällt sie aus, sind alle Websites betroffen. Eine stark ausgelastete Website kann andere ausbremsen, daher sind Grenzen und Isolation unerlässlich (aruaru-llm hat bereits eine Parallelitätsgrenze und eine faire Warteschlange). Auch die Trennung der Websites voneinander erfordert Sorgfalt.
