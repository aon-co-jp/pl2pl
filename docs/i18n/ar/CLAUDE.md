# ملاحظات تطوير pl2pl
- **المهمة**: أداة تعيد كتابة الشيفرة بين اللغات والأطر (frameworks) وأنظمة التشغيل (مكتوبة بـ Rust، في `src/`). اللغات المصدرية مسرودة في `docs/LANGUAGES.md`، والتركيبات في `docs/COMBINATIONS.md`. يكتب المالك التصميم في `docs/DESIGN.md` شيئًا فشيئًا. **لا تختلق المواصفات نيابةً عنه أبدًا.**
- **الاتجاه**: إعادة كتابة «من كثير إلى كثير» بين اللغات المعروفة. لا نبني كل شيء دفعة واحدة؛ نبدأ بما نختاره. الموقع الإلكتروني فيه الشروحات والتنزيلات فقط. أما إعادة الكتابة فتجري في تطبيق الحاسوب.
- **القواعد**: ما لا يمكن إعادة كتابته يبقى `TODO` ويُبلَّغ عنه (لا يُخفى أبدًا). كن حذرًا (إذا احتُمل وجود اعتماديات أو آثار جانبية فلا تغيّر). شغّله فعليًّا قبل أن تقول «تم». لا REST جديد. الرد بالياباني فقط.
- **الشكل المشترك (IR)**: `src/ir.rs` (الأنواع وأجسام الدوال والنماذج والوسائط البرمجية والقوالب) وجانب الكتابة في `src/ir_emit.rs`. جانب الإدخال (PHP وPython وJava) وجانب الإخراج (JSON وOpenAPI وFastAPI) منفصلان لتسهيل إضافة تركيبات جديدة. و`pl2pl php` يمرّ أيضًا عبر أداة الكتابة نفسها؛ وأي تغيير يجب ألا يبدّل المخرجات يُثبَت بأن الفرق (diff) بين المخرجات قبله وبعده فارغ. أبلغ عن الملفات التي لم يُعثر فيها على أي مسار (route). وتحقّق من المخرجات فعليًّا، مثلًا بـ `py_compile`.
- **PHP**: `src/php.rs` و`src/blade.rs` و`src/middleware.rs`. الاختبار الشامل: `tests/run-php.sh` (FastAPI وSQLite وJinja2 حقيقية). اختبارات الوحدات: `cargo test --release`. في WSL: `wsl -d Ubuntu -- bash <file>`.
- **اللحاق التلقائي**: `pl2pl watch` (`src/watch.rs` و`registry/ecosystem.toml`). البنود التي أمر التحقق فيها فارغ تُعرض «غير مفحوصة» فقط ولا تُحدَّث تلقائيًّا أبدًا. تمرّ التنبيهات عبر `--notify-file` في version-control.
- **النشر**: صفحة الشرح هي `webpage/index.html`. على VPS: `/root/easy-web.tokyo/pl2pl` (يُحدَّث بـ `git pull`؛ وهو ثابت فلا حاجة لإعادة التشغيل)، و`pl2pl-web.service` على المنفذ 8142، وقد أُضيف إلى `domains.toml`.
- **المطبّات**: اكتب الملفات التي فيها يابانية بـ Python مع `-X utf8`. أبقِ سكربتات الصَّدَفة (shell) بنهايات أسطر LF. يعيد Git Bash كتابة المسارات `/mnt/...`. وللنصوص الكثيرة العلامات الاقتباسية أو `\` استخدم أداتَي Write / Edit لا heredoc.
- **COBOL_to / Java_to**: دُمجا في `converters/`. حذف المستودعين الأصليين لا رجعة فيه، فاطلب موافقة نهائية أولًا.
- **نظام الترجمة** (للُّغة البشرية) منفصل عن المحوِّلات. والمحوِّلات لا تعتمد على LLM.
- **لغات الوثائق**: الملفات اليابانية هي الأصل. أُعيدت كتابة الملفات الإنجليزية بكلمات بسيطة. أما اللغات الثماني الأخرى (`docs/i18n/`) فهي ترجمات بالذكاء الاصطناعي للمحتوى نفسه (لم يراجعها متحدثون أصليون من البشر بعدُ). وتاريخ الأمور السابقة في `docs/HISTORY-ja.md`.

## الجديد (من 2026-11-22 إلى 2026-11-23)
- COBOL (`converters/cobol_to`): أُضيفت `SORT` (`USING` / `GIVING` و`INPUT` / `OUTPUT PROCEDURE` و`RELEASE` و`RETURN`) و`MERGE` و`SEARCH` / `SEARCH ALL` و`INSPECT ... LEADING` / `CHARACTERS`. كما أصبحت صيغتا الاستخدام `COMP-3` و`COMP` مقروءتين.
- SQL المضمَّن: `EXEC SQL` (المؤشرات و`FETCH` و`SELECT ... INTO`) و`WHENEVER` والمتغيرات المؤشِّرة (بما فيها صيغة الكلمة المفتاحية `INDICATOR`) و`SQLSTATE` و`EXECUTE IMMEDIATE` و`PREPARE` / `EXECUTE ... USING`. جرى تشغيل شيفرة Python المولَّدة فعلًا؛ أما جانب Rust فلم يُفحص إلا بمعالج تجريبي.
- `EXEC CICS` (حدٌّ أدنى): `SEND TEXT` تعرض نصًّا، و`RETURN` / `ABEND` تُنهيان البرنامج. تبقى بقية الأوامر على هيئة `TODO`. ولا تُحوَّل خرائط الشاشة BMS.
- Java (`converters/java_to`): مراجع الدوال و`Comparator` و`Collectors` والأصناف المجهولة (تُحفظ كل الدوال). في جانب Rust تعمل عمليات List (`Vec` و`push` والوصول بالفهرس و`for`)، وتجتاز شيفرة Rust المولَّدة `cargo check` مع spring وjaxrs وservlet وspark.
- تجربة على Spring PetClinic REST (مشروع ينطلق من OpenAPI): ارتفع عدد المسارات المكتشفة من 1 إلى 37؛ وفي شيفرة Python المولَّدة 0 أخطاء نحوية؛ وتعمل الاستعلامات المشتقة (`Or` و`Like` والمقارنات و`OrderBy` وغيرها) على مستودع في الذاكرة؛ ويمكن استيراد التطبيق (41 مسارًا)؛ وقد توحّدت أسماء `this.field`، فصار الاستدعاء يمر بالمتحكّم ثم الخدمة ثم المستودع.
- ما يزال مفتوحًا: توليد المستودع والمُحوِّل MapStruct (تتوقف الاستدعاءات عند `TODO`)، وقاعدة بيانات حقيقية، وتشغيل حقيقي لـ FastAPI المولَّد، وخرائط CICS وملفاتها، وأجسام Rust التي تحوي Map أو Stream. اختبارات pl2pl: نجح 55.

## سياسة Versionless API (2026-11-25)
واجهات برمجة التطبيقات (API) في هذا المستودع **Versionless** (دون رقم إصدار): لا نضع `v1` ونحوه في عناوين URL ولا في أسماء الحزم، وتتطور الواجهات بالإضافة فقط دون كسر التوافق. نُضيف الحقول فقط، والحقول المضافة اختيارية، ونتجاهل الحقول غير المعروفة، وعند تغيير اسم نُضيف الاسم الجديد ونعلن الاسم القديم متقادمًا (الأجل الافتراضي 6 أشهر أو أكثر، ولا نحذف إلا بعد التأكد من أن الاستخدام صفر)، ونقبل القيم غير المعروفة في enum، والاستثناء هو الإصلاحات الأمنية العاجلة. تبقى أسماء `.v1` الحالية في الوقت الحاضر كي لا ينكسر المستدعون، ونضيف اسمًا بديلًا بلا رقم إصدار ثم نتخلص من `.v1` على مراحل. التفاصيل والمصادر في آخر ملف [`runo/API-POLICY.md`](https://github.com/aon-co-jp/runo/blob/main/API-POLICY.md). يجري التطبيق تباعًا من الآن.

## سياسة API: إلغاء REST كليًّا والانتقال إلى gRPC / Connect
**لا نُنشئ أي REST API جديدة** في هذا المستودع. الواجهات التي تُستدعى من المتصفح أو `curl` تستخدم **استدعاءات Connect البسيطة** (`POST /<package>.<Service>/<Method>` مع `content-type: application/json`)، والاتصال بين الخدمات يستخدم **gRPC / gRPC-web**. وGraphQL للقراءة فقط. وتُنقل واجهات REST القديمة عند تعديلها، ويُحذف المسار القديم بعد نقلها. وتُقرأ بيانات JSON بـ RS-JSON (`from_str_secure` / `parse_secure`). والاستثناء الوحيد هو ما يحدّد معيارُ الطرف الآخر شكلَه (ACME وعمليات رد النداء في OAuth/OIDC وWebhook الجهات الخارجية وفحوص الصحة والملفات الثابتة وOTLP). وعند الشك نستخدم Connect. المرجع الأصلي: [`runo/API-POLICY.md`](https://github.com/aon-co-jp/runo/blob/main/API-POLICY.md).
