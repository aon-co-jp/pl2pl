# pl2pl — заметки для разработки
- **Задача**: инструмент, который переписывает код между языками, фреймворками и операционными системами (написан на Rust, лежит в `src/`). Исходные языки перечислены в `docs/LANGUAGES.md`, сочетания — в `docs/COMBINATIONS.md`. Проект владелец понемногу пишет в `docs/DESIGN.md`. **Никогда не придумывайте спецификацию за него.**
- **Направление**: переписывать «многие во многие» между известными языками. Не строить всё сразу, а начинать с выбранного. На сайте только инструкции и загрузка. Переписывание выполняется в приложении для ПК.
- **Правила**: то, что нельзя переписать, остаётся как `TODO` и попадает в отчёт (никогда не прятать). Действовать осторожно (если возможны зависимости или побочные эффекты — ничего не менять). Прежде чем сказать «готово», запустить по-настоящему. Новых REST не делать. Отвечать только по-японски.
- **Общий вид (IR)**: `src/ir.rs` (типы, тела функций, модели, middleware, шаблоны) и записывающая сторона в `src/ir_emit.rs`. Входная сторона (PHP, Python, Java) и выходная (JSON, OpenAPI, FastAPI) разделены, чтобы новые пары добавлялись легко. `pl2pl php` тоже идёт через ту же запись; если изменение не должно менять вывод, докажите это пустым diff вывода до и после. Файлы, где маршруты не найдены, попадают в отчёт. Вывод нужно проверять по-настоящему, например через `py_compile`.
- **PHP**: `src/php.rs`, `src/blade.rs`, `src/middleware.rs`. Сквозной тест: `tests/run-php.sh` (настоящие FastAPI, SQLite, Jinja2). Модульные тесты: `cargo test --release`. В WSL: `wsl -d Ubuntu -- bash <file>`.
- **Автоматическое слежение за версиями**: `pl2pl watch` (`src/watch.rs`, `registry/ecosystem.toml`). Записи без команды проверки только показываются как «не проверено» и сами никогда не обновляются. Оповещения идут через `--notify-file` в version-control.
- **Развёртывание**: страница-визитка — `webpage/index.html`. На VPS: `/root/easy-web.tokyo/pl2pl` (обновляется через `git pull`; страница статическая, перезапуск не нужен), `pl2pl-web.service` на порту 8142, уже добавлен в `domains.toml`.
- **Подводные камни**: файлы с японским текстом писать через Python `-X utf8`. Shell-скрипты держать с LF. Git Bash переписывает пути `/mnt/...`. Для текста со множеством кавычек или `\` использовать инструменты Write / Edit, а не heredoc.
- **COBOL_to / Java_to**: уже включены в `converters/`. Удаление исходных репозиториев необратимо — сначала получить окончательное согласие.
- **Система перевода** (человеческий язык) отделена от конвертеров. Конвертеры не опираются на LLM.
- **Языки документации**: японские файлы — оригиналы. Английские файлы переписаны простыми словами. Остальные восемь языков (`docs/i18n/`) — перевод того же содержания, сделанный ИИ и проверенный ИИ на естественность (живой носитель языка пока не проверял). Более ранняя история: `docs/HISTORY-ja.md`.

## 2026-11-25 Дополнение: поддержка @Mapping из MapStruct

`@Mapping(target=..., source="a.b")` (вложенный исходный атрибут), `ignore=true` и `constant="..."` на методах маппера теперь передаются в сгенерированный Python-метод `MapperBase._to(cls, src, rename, ignore, const)`. ## Политика Versionless API (2026-11-25)
API этого репозитория — **Versionless**: в URL и именах пакетов нет `v1` и подобных суффиксов, а развивается он только добавлением, не ломая совместимость. Поля только добавляем; новые поля необязательны; незнакомые поля игнорируем; переименование делаем так: добавляем новое имя, а старое объявляем устаревшим (срок по умолчанию — не меньше 6 месяцев, удаляем только после проверки, что оно нигде не используется); для enum допускаем неизвестные значения; исключение — срочные исправления безопасности. Существующие имена с `.v1` пока остаются, чтобы не сломать вызывающий код: мы добавляем псевдоним без версии и поэтапно убираем `.v1`. Подробности и источники — в конце [`runo/API-POLICY.md`](https://github.com/aon-co-jp/runo/blob/main/API-POLICY.md). Внедрение идёт шаг за шагом.

## Политика API: отказ от REST, переход на gRPC / Connect
В этом репозитории **новые REST API не создаются**. API, которые вызывают из браузера и через `curl`, делаем как **простые вызовы Connect** (`POST /<пакет>.<Service>/<Method>`, `content-type: application/json`); между сервисами используем **gRPC / gRPC-web**. GraphQL — только для чтения. Существующий REST переносим, когда до него доходят руки, а после переноса старый маршрут удаляем. JSON читаем через RS-JSON (`from_str_secure` / `parse_secure`). Исключения — только там, где форму задаёт чужой стандарт (ACME, колбэки OAuth/OIDC, вебхуки третьих сторон, проверки работоспособности, статические файлы, OTLP). Если сомневаетесь — берите Connect. Первоисточник — [`runo/API-POLICY.md`](https://github.com/aon-co-jp/runo/blob/main/API-POLICY.md).
