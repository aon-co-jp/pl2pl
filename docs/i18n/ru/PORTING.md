# pl2pl — передача дел
(Более ранние подробные записи — в `docs/HISTORY-ja.md`, на японском.)

## Где мы сейчас (2026-11-19)
- Выпущена версия 0.1.0 с установщиками для Windows, Linux и Mac и тестами в CI.
- PHP → FastAPI проверен сквозным тестом на настоящем FastAPI: маршруты, Eloquent, построитель запросов, Blade, middleware, связи и семейство `@can`.
- `pl2pl web` теперь тоже узнаёт PHP.
- `pl2pl watch` находит новые версии, тестирует их, исправляет проблемы, а если ничего не помогает — отправляет оповещение. GitHub тоже каждый вечер и каждое утро тестирует на самых новых версиях.
- `pl2pl ir` (пробная версия) приводит маршруты PHP, Python и Java (Spring, JAX-RS, Servlet, Spark) к общему виду и выдаёт JSON, OpenAPI или заготовку FastAPI. IR несёт также типизированные параметры, тела функций, модели, middleware и шаблоны, а `pl2pl php` теперь записывает вывод через общий эмиттер в `src/ir_emit.rs` (вывод не изменился; 49 сквозных проверок проходят).
- Страница с описанием и загрузкой работает: <https://easy-web.tokyo/pl2pl/> (на VPS, статическая). Есть также карточка на главной странице easy-web.tokyo.
- COBOL_to и Java_to включены в `converters/`.

3. `watch` испытан на настоящей новой версии: с fastapi 0.165.0 (starlette 1.10) `tests/run-php.sh` прошёл 49 проверок, поэтому проверенная версия в реестре повышена до 0.165. Осталось: новые laravel 13 / django 6.1 / spring-boot 4.1 остаются «непроверенными», так как сквозные тесты не используют настоящие фреймворки (пока таких тестов нет — только отчёт).
4. Настроить вечерний и утренний запуски на компьютере (пока не сделано: команда проверки на этом ПК не работает и давала бы ложные тревоги; пример — в начале `scripts/pl2pl-watch.cmd`).
5. (Готово) Карточка pl2pl размещена на главной странице easy-web.tokyo и работает в продакшене (open-easy-web `95cb1e7`; старый бинарник — `server/target/release/open-easy-web-server.before-pl2pl-card-20261119`).
6. PHP (готово, с ограничениями): `@php` в Blade теперь превращает присваивания и `++` `--` `+=` `-=` `*=` `/=` `.=` в `{% set %}`; работают `$attributes` как вывод, `->merge` (строковые значения или преобразуемые выражения), `->class([...])` (список строк), `->only` и `->except`; `morphToMany` (столбец типа в связующей таблице); и компоненты Blade в виде классов (`app/View/Components/*.php`: аргументы конструктора становятся значениями по умолчанию и `_props`, а `view('x.y')` в `render()` отслеживается) (55 сквозных проверок, 41 модульный тест). Осталось: публичные методы класса-компонента (`{{ $method() }}` в его шаблоне остаётся TODO, отчёт считает их), `->class()` с ключами (условный) и `@php` с if/foreach или вызовами функций (остаётся TODO).
7. Связка с aruaru-llm (готово): 2026-11-19 мы подтянули aruaru-llm v0.2.5 и выполнили настоящий `pl2pl llm setup`. Автоматический выбор, 3B, не удался, потому что его веса разбиты на части (shards), поэтому теперь установка переходит к следующей, меньшей модели (если модель не задана явно). `GenerateQwen` возвращает текст с qwen2.5-1.5b-instruct (около 2,9 ГБ, на CPU). **`pl2pl php --explain`** (необязательно; `--explain-max N`, по умолчанию 3) добавляет заметку ИИ под каждым пунктом TODO в отчёте. Замер: около 2 минут на пункт на CPU, а **качество плохое и порой неверное** (1 из 2 мимо цели), поэтому по умолчанию выключено. Перезапущенный aruaru-llm не имеет выбранной модели (400), поэтому сначала выбирается установленная. **Модель побольше (около 12 ГБ)**: самая большая в каталоге aruaru-llm — 3B (около 6,2 ГБ), а 3B и 7B поставляются несколькими файлами-частями, которые нынешний установщик скачать не может. Сначала — поддержка частей (в aruaru-llm) и скорость на CPU (уже на 1.5B она такая медленная). Kokkos на GPU и ядра на open-cuda / open-directx пока не проверены. **GPU (проверено 2026-11-19)**: на GeForce GT 730 (2 ГБ, sm_35, драйвер 475 = класс CUDA 11.4) мы без прав администратора установили nvcc из CUDA 11.8 через micromamba (канал conda от NVIDIA), запустили простое ядро CUDA и вывод `pl2pl gpu --target open-cuda` (`vec_loop12.cu`) на настоящем GPU и увидели 0 расхождений с CPU (`tests/gpu-check.ps1`). Подводные камни: MSVC 14.44 требует `-D_ALLOW_COMPILER_AND_STL_VERSION_MISMATCH` и `-allow-unsupported-compiler`; в PyPI нет nvcc для Windows; CUDA 12 не умеет целиться в sm_35. **Всё ещё не проверено**: бэкенд Kokkos CUDA и запуск на open-cuda (реализация на Rust) и open-directx.
8. Удалить исходные COBOL_to и Java_to (**необратимо: сначала получить окончательное согласие**).
9. `docs/DESIGN.md` пишет владелец. 2026-11-19 мы перечитали `docs/LANGUAGES.md` и не нашли расхождений с текущим состоянием (у Java и COBOL есть конвертеры). Это по-прежнему список «по знаниям», а не сверенный со свежим поиском в вебе.

## Что нового в v0.2.1 (2026-11-20)
- Если в `pl2pl web --backend` выбрать `rpoem` / `rporea`, показываются пояснения (на японском и английском): RPoem уже включает совместимость с Tauri и WunderGraph Cosmo, tokio и WASM, поэтому отдельно их выбирать не нужно; HTML5 и CSS3 используются, но понемногу; JavaScript, TypeScript, Node.js и REST по замыслу не используются. То, что добавлено через `--also` и уже включено, отклоняется (код выхода 2); то, что включено, но ещё не зрелое, можно выбрать — с предупреждением.
- `pl2pl maturity [--repo DIR] [--llm URL] [--apply]` оценивает эту зрелость, запуская пробные тесты (реестр: `registry/maturity.toml`). Мнение ИИ из aruaru-llm само по себе вердикт не меняет.
- Для стеков, кроме RPoem / RPoRea, `--also nodejs` (или `next.js`) принимается с пояснением: мы не навязываем правило «без Node.js», но и не рекомендуем его. Показываются альтернативы для выбранного языка (RPoem / RPoRea + Reaxt, FastAPI + Jinja2, RS-Node.js и другие, которые мы не проверяли).
- Родственные репозитории, которые развиваются вместе: Reaxt, RPoRea, RPoem, RMojo, open-cosmo, RS-TypeScript, RS-JavaScript, RS-Node.js и pl2pl. Когда меняется один, остальные проверяются в тот же день.
- `pl2pl info [ui|nojs|json|connect|shared] [--lang ...]` и `webpage/info.html` объясняют принципы проектирования RPoRea / RPoem с плюсами и минусами на 11 языках.
- Исходные `COBOL_to` / `Java_to` сохранены (не удалены); объединённые копии в `converters/` дали идентичный вывод.

- Встроенный SQL: `EXEC SQL` (курсоры, `FETCH`, `SELECT ... INTO`), `WHENEVER`, индикаторные переменные (в том числе запись с ключевым словом `INDICATOR`), `SQLSTATE`, `EXECUTE IMMEDIATE`, а также `PREPARE` / `EXECUTE ... USING`. Сгенерированный Python действительно запускали; для Rust проверка сделана только с условным обработчиком.
- `EXEC CICS` (минимально): `SEND TEXT` выводит текст, а `RETURN` / `ABEND` завершают программу. Остальные команды остаются как `TODO`. Карты экранов BMS не воспроизводятся.
