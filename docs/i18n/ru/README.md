# pl2pl

## Что такое pl2pl?
Программы пишут на разных «языках» (языках программирования).
**pl2pl — это инструмент, который переписывает программу с одного языка на другой.**
Например, он может превратить сайт на PHP (Laravel) в сайт на Python (FastAPI).
Работает в Windows, Linux и Mac (версия 0.1.0, ещё в разработке).

- Его устанавливают на свой компьютер. На сайте есть только инструкции и загрузка → <https://easy-web.tokyo/pl2pl/>
- Если pl2pl не может что-то переписать, он это не прячет. Он оставляет `TODO` (пометку «сделать позже») и объясняет причину в отчёте.
- Наша цель — чтобы можно было переписывать между как можно большим числом известных языков.

## Что он умеет сейчас
| Команда | Что делает |
|---|---|
| `pl2pl php` | PHP (Laravel / Symfony) → FastAPI. Подробнее в [PHP.md](../../PHP.md) (на японском) |
| `pl2pl web` | Смотрит в папку, узнаёт Java, COBOL, PHP и Flask/Django и передаёт каждое подходящему инструменту |
| `pl2pl ir` | (пробная версия) Приводит «маршруты» PHP, Python и Java к одному виду и делает из них JSON, OpenAPI или заготовку FastAPI. Преобразование PHP тоже сначала кладёт в эту форму типы, тела функций, модели, middleware и шаблоны, а потом записывает результат |
| `pl2pl watch` | Находит новые версии языков и инструментов и сам подстраивается под них |
| `pl2pl cobol` | COBOL + JCL → GnuCOBOL (Linux) |
| `pl2pl omp` / `kokkos` / `gpu` | Ускоряет циклы C/C++ (gpu — пробная версия) |
| `pl2pl cport` | Делает так, чтобы C-код для UNIX работал и в Windows, и в Linux |
| `pl2pl pyhpc` | Ускоряет вычисления на Python с помощью Numba |
| `pl2pl llm setup` | Устанавливает ИИ-помощника (aruaru-llm). Настоящую установку мы ещё не проверяли |

## Как он сам подстраивается под новые версии
Мы запускаем `pl2pl watch` каждый вечер и каждое утро.
1. Он проверяет, не вышли ли новые версии языков и инструментов (список — в `registry/ecosystem.toml`).
2. Он проверяет работу на новой версии. Если тесты проходят, он сам обновляет «поддерживаемую версию».
3. Если не проходят, version-control (с помощью ИИ) пытается всё исправить.
4. Если и это не помогло, он отправляет сообщение на сохранённые адреса электронной почты и в LINE.

Обратите внимание: для laravel, symfony, flask, django и некоторых других он пока лишь сообщает: «вышла новая версия».
На GitHub тесты с самыми новыми версиями тоже сами запускаются каждый вечер и каждое утро.

## Как пользоваться
```
pl2pl php ./myapp --out ./out
pl2pl web ./project --target fastapi --out ./out
pl2pl ir ./project --out ./out --format openapi
```

## Полезно знать
- pl2pl действует осторожно. Если что-то выглядит рискованным, он оставляет это как есть и объясняет почему. Скорость мы обещать не можем.
- Мы проверяли только небольшие примеры. Большие настоящие программы мы ещё не пробовали.

## Новое в v0.2.0
- Выбирайте сочетание сами: `pl2pl web <dir> --backend <rust-axum|rust-poem|fastapi|mfastapi|rpoem|rporea> [--frontend bootstrap-ts|rust-wasm|none] [--db none|mysql|mariadb|postgres|sqlite] --out <dir>`. COBOL переписывается; C, C++ и Fortran работают как есть, а веб их вызывает.
- `pl2pl c2rust` (простые C и C++) и `pl2pl f2rust` (простой Fortran) создают Rust. `pl2pl cobol --os <linux|macos|unix|windows>` создаёт скрипт сборки для GnuCOBOL.

## Что нового в v0.2.1 (2026-11-20)
- Если в `pl2pl web --backend` выбрать `rpoem` / `rporea`, показываются пояснения (на японском и английском): RPoem уже включает совместимость с Tauri и WunderGraph Cosmo, tokio и WASM, поэтому отдельно их выбирать не нужно; HTML5 и CSS3 используются, но понемногу; JavaScript, TypeScript, Node.js и REST по замыслу не используются. То, что добавлено через `--also` и уже включено, отклоняется (код выхода 2); то, что включено, но ещё не зрелое, можно выбрать — с предупреждением.
- `pl2pl maturity [--repo DIR] [--llm URL] [--apply]` оценивает эту зрелость, запуская пробные тесты (реестр: `registry/maturity.toml`). Мнение ИИ из aruaru-llm само по себе вердикт не меняет.
- Для стеков, кроме RPoem / RPoRea, `--also nodejs` (или `next.js`) принимается с пояснением: мы не навязываем правило «без Node.js», но и не рекомендуем его. Показываются альтернативы для выбранного языка (RPoem / RPoRea + Reaxt, FastAPI + Jinja2, RS-Node.js и другие, которые мы не проверяли).
- Родственные репозитории, которые развиваются вместе: Reaxt, RPoRea, RPoem, RMojo, open-cosmo, RS-TypeScript, RS-JavaScript, RS-Node.js и pl2pl. Когда меняется один, остальные проверяются в тот же день.
- `pl2pl info [ui|nojs|json|connect|shared] [--lang ...]` и `webpage/info.html` объясняют принципы проектирования RPoRea / RPoem с плюсами и минусами на 11 языках.
- Исходные `COBOL_to` / `Java_to` сохранены (не удалены); объединённые копии в `converters/` дали идентичный вывод.

## Что нового (2026-11-22 — 2026-11-23)
- COBOL (`converters/cobol_to`): добавлены `SORT` (`USING` / `GIVING`, `INPUT` / `OUTPUT PROCEDURE`, `RELEASE`, `RETURN`), `MERGE`, `SEARCH` / `SEARCH ALL` и `INSPECT ... LEADING` / `CHARACTERS`. Теперь также читаются формы `COMP-3` и `COMP`.
- Встроенный SQL: `EXEC SQL` (курсоры, `FETCH`, `SELECT ... INTO`), `WHENEVER`, индикаторные переменные (в том числе запись с ключевым словом `INDICATOR`), `SQLSTATE`, `EXECUTE IMMEDIATE`, а также `PREPARE` / `EXECUTE ... USING`. Сгенерированный Python действительно запускали; для Rust проверка сделана только с условным обработчиком.
- `EXEC CICS` (минимально): `SEND TEXT` выводит текст, а `RETURN` / `ABEND` завершают программу. Остальные команды остаются как `TODO`. Карты экранов BMS не воспроизводятся.
- Java (`converters/java_to`): ссылки на методы, `Comparator`, `Collectors` и анонимные классы (все методы сохраняются). В Rust работают операции со списками (`Vec`, `push`, доступ по индексу, `for`), а сгенерированный Rust проходит `cargo check` для spring, jaxrs, servlet и spark.
- Проба на Spring PetClinic REST (проект, который исходит из OpenAPI): найденных маршрутов стало 37 вместо 1; в сгенерированном Python 0 синтаксических ошибок; производные запросы (`Or`, `Like`, сравнения, `OrderBy` и т. д.) работают на репозитории в памяти; приложение можно импортировать (41 маршрут); имена `this.field` теперь совпадают, поэтому вызов проходит контроллер → сервис → репозиторий.
- Ещё не сделано: генерация репозитория и маппера MapStruct (вызовы останавливаются на `TODO`), настоящая база данных, настоящий запуск сгенерированного FastAPI, карты и файлы CICS, а также тела на Rust с Map или Stream. Тесты pl2pl: 55 пройдено.

## 2026-11-25 Дополнение: MFastAPI должен работать из Mojo

MFastAPI сохраняет **спецификацию «можно использовать из Mojo»** (синтаксис Python, ядро на Rust, поддержка Mojo; в Windows настоящий Mojo в WSL запускается через `compat/wsl-bridge` из RMojo). Результат работы 2MFastAPI тоже должен работать из Mojo. Сейчас: `mojo/` — эталонная реализация, а серверы этапов B и C экспериментальные. «Проверено» мы пишем только про то, что действительно запускали. До 11:30 продолжаем автоматически, без вопросов.

## 2026-11-25 Дополнение: c2rust — массивы, break/continue

`pl2pl c2rust` теперь понимает массивы фиксированной длины (`int a[8] = {...};`, `double w[4];`; недостающие начальные значения заполняются нулями), чтение и запись по индексу (`a[j + 1]` → `a[(j + 1) as usize]`), `break;`, `continue;` и `while (1)` → `loop`. Пример с пузырьковой сортировкой и `while (1)` мы собрали и запустили через gcc и rustc в WSL: вывод полностью совпал (`1 2 3 4 5 7 8 9` / `6.00 12.00 9`). Модульные тесты: 56 проходят. Пока нет: указателей, структур, двумерных массивов, передачи массивов в функции и неявного преобразования целых и дробных чисел (`k * 1.5` нужно записывать как `(double)k`).
