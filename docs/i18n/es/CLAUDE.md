# pl2pl – notas de desarrollo
- **Función**: una herramienta que reescribe código entre lenguajes, frameworks y sistemas operativos (hecha en Rust, en `src/`). Los lenguajes de origen están en `docs/LANGUAGES.md` y las combinaciones en `docs/COMBINATIONS.md`. El propietario escribe el diseño en `docs/DESIGN.md`, poco a poco. **Nunca inventes la especificación en su nombre.**
- **Rumbo**: reescribir «de muchos a muchos» entre lenguajes conocidos. No construir todo de golpe; empezar por lo elegido. El sitio web solo tiene guías y descargas. La reescritura se hace en la aplicación de PC.
- **Reglas**: lo que no se pueda reescribir queda como `TODO` y se informa (nunca esconderlo). Ser prudente (si puede haber dependencias o efectos secundarios, no cambiar nada). Ejecutarlo de verdad antes de decir «terminado». Sin nuevos REST. Responder solo en japonés.
- **Forma común (IR)**: `src/ir.rs` (tipos, contenido de las funciones, modelos, middleware, plantillas) y, del lado de escritura, `src/ir_emit.rs`. El lado de entrada (PHP, Python, Java) y el de salida (JSON, OpenAPI, FastAPI) están separados, para que sea fácil añadir pares nuevos. `pl2pl php` también pasa por la misma escritura; para un cambio que no debe alterar la salida, se demuestra con un diff vacío de la salida antes y después. Los archivos sin rutas encontradas se informan. Comprobar la salida de verdad, por ejemplo con `py_compile`.
- **PHP**: `src/php.rs`, `src/blade.rs`, `src/middleware.rs`. Prueba de extremo a extremo: `tests/run-php.sh` (FastAPI real, SQLite, Jinja2). Pruebas unitarias: `cargo test --release`. En WSL: `wsl -d Ubuntu -- bash <file>`.
- **Puesta al día automática**: `pl2pl watch` (`src/watch.rs`, `registry/ecosystem.toml`). Los elementos sin comando de comprobación solo se muestran como «sin comprobar» y nunca se actualizan solos. Los avisos pasan por `--notify-file` de version-control.
- **Despliegue**: la página de presentación es `webpage/index.html`. En el VPS: `/root/easy-web.tokyo/pl2pl` (se actualiza con `git pull`; es estática, así que no hace falta reiniciar), `pl2pl-web.service` en el puerto 8142, ya añadido a `domains.toml`.
- **Trampas**: escribir los archivos con japonés usando Python `-X utf8`. Mantener los scripts de shell en LF. Git Bash reescribe las rutas `/mnt/...`. Para textos con muchas comillas o `\`, usar las herramientas Write / Edit, no un heredoc.
- **COBOL_to / Java_to**: ya integrados en `converters/`. Borrar los repositorios originales no se puede deshacer: pedir antes la aprobación final.
- **Sistema de traducción** (lenguaje humano): separado de los conversores. Los conversores no dependen de un LLM.
- **Idiomas de la documentación**: los archivos en japonés son los originales. Los archivos en inglés se reescribieron en palabras sencillas. Los demás idiomas de `docs/i18n/` son traducciones con IA (aún sin revisión de nativos). Historia anterior: `docs/HISTORY-ja.md`.

## Novedades de la v0.2.1 (2026-11-20)

- Repositorios hermanos que se desarrollan juntos: Reaxt, RPoRea, RPoem, RMojo, open-cosmo, RS-TypeScript, RS-JavaScript, RS-Node.js y pl2pl. Cuando uno cambia, los demás se revisan el mismo día.

## Política de API Versionless (2026-11-25)
Las API de este repositorio son **Versionless**: no se pone `v1` ni similares en las URL ni en los nombres de paquete, y se evoluciona solo añadiendo, sin romper la compatibilidad. Los campos solo se añaden, los campos nuevos son opcionales y los campos desconocidos se ignoran. Para cambiar un nombre se añade el nuevo y se marca el antiguo como obsoleto (el plazo por defecto es de 6 meses o más, y solo se elimina tras confirmar que no se usa en absoluto). Los enum admiten valores desconocidos. Las correcciones urgentes de seguridad son la excepción. Los nombres `.v1` existentes se conservan por ahora para no romper a quien los llama; se añade un alias sin versión y `.v1` se retira por etapas. Detalles y fuentes: al final de [`runo/API-POLICY.md`](https://github.com/aon-co-jp/runo/blob/main/API-POLICY.md). La aplicación se hará paso a paso a partir de ahora.

## Política de API: abolir REST y pasar a gRPC / Connect
Este repositorio **no crea nuevas API REST**. Las API que se llaman desde el navegador o con `curl` usan **llamadas simples de Connect** (`POST /<paquete>.<Service>/<Method>`, `content-type: application/json`); entre servicios se usa **gRPC / gRPC-web**. GraphQL es de solo lectura. El REST existente se migra cuando se toca, y una vez migrado se elimina la ruta antigua. El JSON se lee con RS-JSON (`from_str_secure` / `parse_secure`). Las únicas excepciones son los casos en que el estándar de la otra parte fija la forma (ACME, callbacks de OAuth/OIDC, webhooks de terceros, comprobaciones de estado, archivos estáticos y OTLP). Si hay dudas, Connect. Fuente de verdad: [`runo/API-POLICY.md`](https://github.com/aon-co-jp/runo/blob/main/API-POLICY.md).
