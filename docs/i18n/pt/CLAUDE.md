# pl2pl – notas de desenvolvimento
- **Papel**: uma ferramenta que reescreve código entre linguagens, frameworks e sistemas operacionais (feita em Rust, em `src/`). As linguagens de origem estão em `docs/LANGUAGES.md` e as combinações em `docs/COMBINATIONS.md`. O proprietário escreve o projeto em `docs/DESIGN.md`, aos poucos. **Nunca invente a especificação em nome dele.**
- **Direção**: reescrever «de muitos para muitos» entre linguagens conhecidas. Não construir tudo de uma vez; começar pelo que foi escolhido. O site só tem guias e downloads. A reescrita acontece no aplicativo de PC.
- **Regras**: o que não puder ser reescrito fica como `TODO` e é informado (nunca esconder). Ser cuidadoso (se houver dependência ou efeito colateral possível, não mudar nada). Executar de verdade antes de dizer «pronto». Sem novos REST. Responder somente em japonês.
- **Forma comum (IR)**: `src/ir.rs` (tipos, conteúdo das funções, modelos, middleware, templates) e, do lado da escrita, `src/ir_emit.rs`. O lado de entrada (PHP, Python, Java) e o de saída (JSON, OpenAPI, FastAPI) ficam separados, para facilitar a inclusão de novos pares. O `pl2pl php` também passa pela mesma escrita; para uma mudança que não deve alterar a saída, prova-se com um diff vazio da saída antes e depois. Arquivos sem rotas encontradas são informados. Conferir a saída de verdade, por exemplo com `py_compile`.
- **PHP**: `src/php.rs`, `src/blade.rs`, `src/middleware.rs`. Teste de ponta a ponta: `tests/run-php.sh` (FastAPI real, SQLite, Jinja2). Testes unitários: `cargo test --release`. No WSL: `wsl -d Ubuntu -- bash <file>`.
- **Atualização automática**: `pl2pl watch` (`src/watch.rs`, `registry/ecosystem.toml`). Itens sem comando de verificação só aparecem como «não verificado» e nunca são atualizados sozinhos. Os alertas passam pelo `--notify-file` do version-control.
- **Publicação**: a página de apresentação é `webpage/index.html`. No VPS: `/root/easy-web.tokyo/pl2pl` (atualiza com `git pull`; é estática, então não precisa reiniciar), `pl2pl-web.service` na porta 8142, já adicionado ao `domains.toml`.
- **Armadilhas**: escrever arquivos com japonês usando Python `-X utf8`. Manter os scripts de shell em LF. O Git Bash reescreve caminhos `/mnt/...`. Para textos com muitas aspas ou `\`, usar as ferramentas Write / Edit, não um heredoc.
- **COBOL_to / Java_to**: já incorporados em `converters/`. Apagar os repositórios originais não tem volta: pedir antes a aprovação final.
- **Sistema de tradução** (língua humana): separado dos conversores. Os conversores não dependem de um LLM.
- **Idiomas da documentação**: os arquivos em japonês são os originais. Os arquivos em inglês foram reescritos em palavras simples. Os demais idiomas em `docs/i18n/` são traduções por IA (ainda sem revisão de nativos). Histórico anterior: `docs/HISTORY-ja.md`.

## Novidades da v0.2.1 (2026-11-20)
- Ao escolher `rpoem` / `rporea` em `pl2pl web --backend`, aparecem avisos (japonês e inglês): o RPoem já inclui recursos compatíveis com Tauri e WunderGraph Cosmo, tokio e WASM, então não os escolha à parte; HTML5 e CSS3 são usados, mas em pouca quantidade; JavaScript, TypeScript, Node.js e REST não são usados por projeto. O que for adicionado com `--also` e já estiver incluído é recusado (código de saída 2); o que está incluído mas ainda não é maduro pode ser escolhido, com um aviso.
- `pl2pl maturity [--repo DIR] [--llm URL] [--apply]` julga essa maturidade rodando testes de sondagem (registro: `registry/maturity.toml`). A opinião da IA do aruaru-llm nunca muda sozinha o veredito.
- Com pilhas diferentes de RPoem / RPoRea, `--also nodejs` (ou `next.js`) é aceito com um aviso: não impomos nossa regra de «sem Node.js», mas não o recomendamos. São listadas alternativas para a linguagem escolhida (RPoem / RPoRea + Reaxt, FastAPI + Jinja2, RS-Node.js e outras que não verificamos).
- Repositórios irmãos desenvolvidos juntos: Reaxt, RPoRea, RPoem, RMojo, open-cosmo, RS-TypeScript, RS-JavaScript, RS-Node.js e pl2pl. Quando um muda, os outros são conferidos no mesmo dia.
- `pl2pl info [ui|nojs|json|connect|shared] [--lang ...]` e `webpage/info.html` explicam os princípios de projeto do RPoRea / RPoem, com vantagens e desvantagens, em 11 idiomas.
- Os originais `COBOL_to` / `Java_to` foram mantidos (não apagados); as cópias incorporadas em `converters/` deram saída idêntica.

## Política de API Versionless (2026-11-25)
As APIs deste repositório são **Versionless**: sem `v1` e similares nas URLs nem nos nomes de pacotes; evoluem apenas acrescentando, sem quebrar a compatibilidade. Só se acrescentam campos; os campos novos são opcionais; campos desconhecidos são ignorados; para renomear, acrescenta-se o nome novo e o antigo passa a ser obsoleto (prazo padrão de 6 meses ou mais, e só se remove depois de confirmar que o uso é zero); enums toleram valores desconhecidos; correções urgentes de segurança são a exceção. Os `.v1` existentes ficam por enquanto, para não quebrar quem os chama; acrescenta-se um apelido sem versão e os `.v1` são aposentados por etapas. Detalhes e fontes: o final de [`runo/API-POLICY.md`](https://github.com/aon-co-jp/runo/blob/main/API-POLICY.md). A aplicação será feita aos poucos, em ordem.

## Política de API: fim do REST, rumo a gRPC / Connect
Este repositório **não cria novas APIs REST**. As APIs chamadas pelo navegador ou pelo `curl` usam **chamadas unárias simples do Connect** (`POST /<pacote>.<Service>/<Method>`, `content-type: application/json`); a comunicação entre serviços usa **gRPC / gRPC-web**. GraphQL é somente leitura. O REST existente é migrado quando alguém mexe nele, e a rota antiga é removida depois da migração. O JSON é lido com RS-JSON (`from_str_secure` / `parse_secure`). As únicas exceções são os casos em que o padrão de outra parte define o formato (ACME, callbacks de OAuth/OIDC, webhooks de terceiros, health checks, arquivos estáticos, OTLP). Na dúvida, use Connect. Fonte de verdade: [`runo/API-POLICY.md`](https://github.com/aon-co-jp/runo/blob/main/API-POLICY.md).
